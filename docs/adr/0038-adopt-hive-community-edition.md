# ADR-0038 — Adopt Hive Community Edition (Hive CE) for persistence and code generation

- **Status:** Accepted
- **Date:** 2026-06-01
- **Deciders:** David Ruiz
- **Related:** Supersedes in part ADR-0018; ADR-0016, ADR-0037, `TECHNICAL_SPEC.md` §2, `ROADMAP.md` Phase 4

> This document uses the normative keyword convention defined in
> `CONVENTIONS.md`. Words in **all capitals** (MUST, SHOULD, MAY, etc.)
> carry the meanings defined there.

## Context

ADR-0018 fixed the persistence/codegen toolchain as `hive_flutter` +
`hive_generator 2.0.1`, with a `dependency_overrides: analyzer ^6.4.1`
entry required because `hive_generator 2.0.1` caps `analyzer <7.0.0`.
ADR-0018 explicitly framed the override as temporary: "remove [it] once
`hive_generator` publishes a release that accepts `analyzer >=8.0.0`".

Phase 4 (sub-task 4.1) is the first time code generation actually runs.
It fails:

- The installed toolchain is **Dart 3.11.4 / Flutter 3.41.6**.
- `dart run build_runner build` aborts compiling its own toolchain:
  `dart_style 2.3.8` and `build_resolvers 2.5.4` (pulled in under the
  `analyzer 6.4.1` pin) reference analyzer AST APIs that no longer exist
  on this SDK (`MixinOnClause`, `ExtensionDeclaration.onClause`,
  `AnalysisDriverFilesystem.FileSource`).
- The latest published `hive_generator` is **2.0.1** — the package is
  unmaintained. There is no release that accepts `analyzer >=8.0.0`, so
  the override's documented exit condition can never be met.

In short, ADR-0018's codegen path is a dead end on a current SDK. The
maintained successor is **Hive Community Edition (Hive CE)** — a fork of
Hive that tracks modern Dart/analyzer. It keeps the same public API
(`@HiveType` / `@HiveField`, `TypeAdapter`, `Box`, `Hive`), so models and
data sources are essentially unchanged. `hive_ce_generator` supports the
current analyzer and runs cleanly under `build_runner` (it resolves to
1.11.1 on this SDK; the newer 1.11.2 needs `analyzer ^12` → `meta ^1.18`,
which the Flutter SDK's pinned `meta 1.17.0` blocks — see the `pubspec.yaml`
note, no analyzer override required).

## Decision

The project adopts **Hive CE** for local persistence and adapter code
generation, replacing the original Hive packages:

| Role | Was (ADR-0018) | Now (this ADR) |
|---|---|---|
| Persistence (prod) | `hive_flutter` | `hive_ce_flutter` (with `hive_ce` core) |
| Code generation (dev) | `hive_generator` | `hive_ce_generator` |
| Toolchain pin | `dependency_overrides: analyzer ^6.4.1` | **removed** |

Specifics:

1. Production code imports Hive symbols from Hive CE
   (`package:hive_ce_flutter/hive_ce_flutter.dart`, which re-exports the
   `hive_ce` core). Annotations remain `@HiveType` / `@HiveField`.
2. Adapters are generated by `hive_ce_generator` via `build_runner` and
   the generated `*.g.dart` files are committed — preserving ADR-0018's
   "commit generated files so CI does not run codegen" rule.
3. The `dependency_overrides: analyzer ^6.4.1` entry is **removed**.
   Hive CE's toolchain resolves against the current analyzer without a
   pin.
4. The `typeId` registry and model design fixed by ADR-0037 are
   unchanged. Adapters are registered per type at box-opening time.
5. Hive CE reads/writes the same on-disk binary format as Hive. The app
   is greenfield (no shipped data), so no migration is required.

## Consequences

### Positive
- Code generation works on the current Dart/Flutter SDK.
- The `analyzer` override is removed, simplifying version solving and
  eliminating a pin that could never be lifted under ADR-0018.
- ADR-0018's intent — generated, committed adapters, no hand-written
  serialization — is preserved.
- Hive CE is actively maintained, reducing future toolchain risk.

### Negative
- A dependency swap: three package names change
  (`hive_flutter`→`hive_ce_flutter`, add `hive_ce`,
  `hive_generator`→`hive_ce_generator`) and imports move from
  `package:hive*` to `package:hive_ce*`.
- Introduces a community fork in place of the original package. Mitigated
  by Hive CE's API compatibility and active maintenance.

### Neutral
- The on-disk format is unchanged, so the choice is invisible at runtime.

## Alternatives considered

### Option A — Hand-write the `TypeAdapter`s (no codegen)
Rejected. ADR-0018 already rejected hand-written adapters as mechanical
and error-prone, and codegen remains the intent. (It would, however, also
remove the broken toolchain and the analyzer override.)

### Option B — Pin the old toolchain / downgrade the SDK
Rejected. `hive_generator` is frozen at 2.0.1 and its analyzer range is
incompatible with the installed SDK; there is no compatible newer
toolchain, and downgrading the developer/CI SDK to chase an unmaintained
package is not sustainable.

### Option C — Keep `hive_generator`, wait for an analyzer-8 release
Rejected. The package is unmaintained; the awaited release does not
exist, so this blocks Phase 4 indefinitely.

## Follow-ups

- None. The `analyzer` override and its removal-tracking follow-up from
  ADR-0018 are closed by this decision.
